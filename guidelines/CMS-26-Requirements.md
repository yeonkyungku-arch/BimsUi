## 요청사항

CMS 서비스의 세 가지 방향으로 기능 추가 및 수정이 요청되었습니다.

## 요청한 이유

### 글로벌 버전 개발

- **다국어/다국가 서비스 확장**: 현재 한국 중심으로 구축된 서비스를 해외 시장에 제공하려면 UI 언어 변경, 국가별 전화번호 및 사업자번호 입력 형식 지원이 필수적이다.
- **사업자/식별번호 입력 구조 한계**: 기존 3-2-5 고정 형식은 한국 사업자번호 전용으로 해외 등록번호 형식을 수용할 수 없다.
- **운영시간 타임존 미반영 문제**: 해외 거점 미디어그룹의 운영시간이 서버 기준 시간으로만 관리되어 현지 실제 운영시간과 불일치가 발생한다.
- **IR 센서 데이터 수집 부재**: 시청자 반응 데이터를 활용한 광고 효과 분석을 위해 IR 센서 수집 인프라가 필요하다.

### 서비스 시장 확장

- **ColorLight LED 셋탑 신규 지원 필요**: 기존 Quber 셋탑 전용으로 개발된 앱을 ColorLight LED 셋탑에서도 동작하도록 확장해야 새로운 하드웨어 파트너사와 협업이 가능하다.
- **LG 디스플레이 연동 수요**: LG 디스플레이 전용 제어 API 연동을 통해 LG 디스플레이를 사용하는 고객사를 대상으로 서비스를 확대할 필요가 있다.

### 서비스 고도화

- **명령 전송 안정성 문제**: 서버에서 디바이스로 직접 명령을 전송하는 구조에서 네트워크 불안정 시 명령 유실이 빈번하게 발생하여 운영 신뢰도가 낮다.
- **로그 유실 문제**: 네트워크 단절 시 셋탑 로그가 유실되어 재생 이력 및 장애 원인 추적이 불가능한 상황이 발생한다.
- **효과 리포트 오류 및 데이터 왜곡**: 동일 지점에 복수의 미디어그룹이 설치된 경우 성별/연령 등 지표가 중복 집계되어 광고 효과 수치가 왜곡된다.
- **스케줄 순서 변경의 즉시 반영 위험**: 현재 순서 변경이 즉시 셋탑에 반영되어 운영 중 실수로 인한 방송 사고 위험이 있다.
- **편성 관리 기능 부재**: 날짜별 독립 편성 관리 및 게첨 보고 모드가 없어 특정 행사나 캠페인 기간 운영에 어려움이 있다.
- **UX 불편함**: 대용량 데이터 환경에서 개별 항목 관리에 시간이 소요되며, 리포트 진입 동선이 복잡하고 그래프 가독성이 낮다.

## 수정사항

### 계정/회원 정보 영역

- 프로필 설정에 언어 선택(ko/en) 기능 추가 및 선택값을 DB에 저장하여 로그인 유지
- 회원가입/수정 화면에 국가 선택 필드(countryCode) 추가
- 전화번호 입력을 국가별 유효성 검증이 가능한 구조로 변경 (E.164 등 표준 저장 방식 논의 필요)
- 사업자/식별번호 입력 필드를 3-2-5 고정 형식에서 단일 자유 입력 필드로 전환

## 이렇게 수정한 이유

### 글로벌 대응 방식

- **언어 설정을 서버 저장 방식으로 선택**: 브라우저 로컬 저장만으로는 다중 기기 접속 시 언어 설정이 유지되지 않으므로 DB에 languageCode를 저장하여 어느 기기에서도 일관된 언어 경험을 제공한다.
- **단일 자유 입력 필드로 전환**: 국가마다 사업자/식별번호 자릿수와 형식이 다르므로 고정 형식을 제거하고 단일 입력 필드로 전환하여 글로벌 확장성을 확보한다. 입력값 인증 정책은 추후 논의(TBD)로 남겨 유연성을 유지한다.
- **타임존 기반 운영시간 관리**: 서버는 UTC 기준으로 통일하고 클라이언트 및 셋탑은 저장된 타임존으로 변환하는 방식을 검토한다. 단, 안드로이드 셋탑이 현지 시간을 자체 적용하는 방식인지 서버에서 계산하는 방식인지 확인이 필요하다.

### 데이터 정확성 확보

- **대표 묶음 매핑 방식 선택**: 동일 지점의 미디어그룹을 코드 수준에서 자동으로 묶는 것은 오분류 위험이 있어 수동 매핑(mappingGroupId)을 우선 적용하고, 이후 자동화 고도화를 검토한다.
- **지표별 집계 규칙 적용**: 성별/연령과 같은 분포 지표는 단순 합산이 아닌 대표값(또는 가중평균) 방식이 통계적으로 올바르므로 지표 유형별 계산 규칙을 별도로 정의한다.
- **스케줄 매핑 우선순위 기준 명시 필요**: 스케줄-성과 데이터 연결 시 동일 시간대에 복수 스케줄이 있을 경우를 대비해 연결 키 및 우선순위 기준을 정책으로 확정한다(TBD).

### 운영 안정성 확보

- **편집 모드 + 반영 단계 분리**: 운영 중 순서 변경이 즉시 반영되면 현재 재생 중인 광고가 중단될 수 있다. 편집 모드 진입 후 별도 확정 버튼을 눌러야 전송되는 구조로 변경하여 의도치 않은 방송 사고를 방지한다.
- **게첨 보고 스냅샷 기반 복원**: 게첨 보고 적용 전 상태를 스냅샷으로 보존하여 보고 종료 후 정확하게 원래 상태로 복원한다. 스냅샷 기준 및 복원 정책은 추후 확정(TBD).
- **Gateway를 통한 명령 중계**: 서버-디바이스 직접 전송 구조는 네트워크 불안정 시 재전송 로직이 없어 명령이 유실된다. Gateway를 중간에 두어 중복 제거 및 재전송을 관리하고 ACK를 2단계(수신 확인 + 적용 완료)로 강화한다.
- **로컬 버퍼링 + 배치 전송**: 로그를 발생 즉시 전송하되 실패 시 로컬에 저장하고 연결 복구 시 배치로 전송하는 방식을 택하여 데이터 유실 없이 이력을 보존한다. 저장공간 용량 및 중복 방지 기준은 정책 논의 필요.

### UX 개선 원칙

- **다중 선택 + 일괄 액션**: 콘텐츠/스케줄/미디어 수가 많은 고객사 환경에서 개별 처리는 비효율적이므로 체크박스 기반 다중 선택을 도입하고 일괄 삭제/복제를 지원한다. 부분 실패 시 성공/실패 목록을 구분하여 사용자에게 명확한 피드백을 제공한다.
- **재생로그 요약/상세 분리**: 대부분의 사용자는 집계 수치(평균 재생횟수, 최근 송출시간)만 필요하므로 요약 탭을 기본으로 제공하고, 상세 추적이 필요한 경우에만 이벤트 단위 로그를 별도 탭에서 조회하도록 구분하여 성능과 가독성을 모두 확보한다.
- **Soft Delete / Hard Delete 정책 명문화**: 현재 삭제 방식이 리소스 유형별로 통일되지 않아 운영자가 혼란을 겪는다. 유형별 삭제 방식(콘텐츠·스케줄: Soft, 미디어: Hard 등)을 정책으로 확정하고 UI에서 가이드를 제공한다.
- **ColorLight 앱을 기존 소스 기반으로 구축**: 완전 신규 개발보다 기존 Quber 앱 소스에서 의존 기능을 목록화하고 동등/대체/미지원 여부를 분류한 뒤 ColorLight에 맞게 포팅하는 방식으로 개발 기간을 단축한다.
