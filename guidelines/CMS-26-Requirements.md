# CMS-26 기능별 요청사항 및 수정 내역

---

## CMS-26-001 | 언어 설정(변경)
> 글로벌 버전 개발 | 계정 정보(회원정보) | 우선순위: highest

### 요청사항
프로필에서 언어(한국어/영어)를 선택하면 서비스 UI는 물론, 이메일·알림·리포트(다운로드/PDF) 문구까지 선택한 언어로 통일되었으면 합니다.

### 요청한 이유
해외 파트너사 및 글로벌 광고주와 CMS를 함께 사용해야 하는데 현재 한국어만 지원되어 영어권 사용자가 서비스를 이용하는 데 큰 불편이 있습니다.

### 수정사항
- 프로필 > 설정 화면에 언어 선택(ko/en) UI 추가
- languageCode 기반으로 서비스 전체 UI 언어 전환 적용
- 이메일/알림 발송 시 사용자 languageCode에 맞는 템플릿 사용
- 리포트(다운로드/PDF) 생성 시 languageCode 기반 문구 적용
- 미지원 코드 입력 시 ko fallback, 번역 키 누락 시 기본 언어 표시

### 이렇게 수정한 이유
사용자가 선택한 언어가 UI에만 적용되고 이메일·알림에서는 다른 언어로 나오면 인지 일관성이 깨져 혼란을 준다. 모든 접점에서 동일 언어를 유지하여 사용자가 "내 설정이 제대로 반영됐다"는 신뢰감을 가질 수 있도록 한다.

## CMS-26-002 | 언어 설정 유지
> 글로벌 버전 개발 | 계정 정보(회원정보) | 우선순위: highest

### 요청사항
한 번 설정한 언어가 로그아웃 후 재로그인해도 유지되었으면 합니다.

### 요청한 이유
현재는 로그인할 때마다 언어를 다시 설정해야 하는 번거로움이 있고, 여러 기기에서 접속할 때도 같은 언어가 유지되지 않아 불편합니다.

### 수정사항
- languageCode를 사용자 프로필 DB에 저장
- 로그인 시 저장된 languageCode 우선 적용, 미설정 시 ko 기본값
- 저장값 손상 또는 미지원 코드인 경우 ko로 자동 적용

### 이렇게 수정한 이유
로그인할 때마다 언어를 다시 설정해야 한다면 사용자는 반복 작업을 강요받는 느낌을 받는다. 설정을 기억해주는 것은 "시스템이 나를 알아본다"는 경험을 주어 서비스 신뢰도를 높인다.

## CMS-26-003 | 회원정보-국가 선택 추가
> 글로벌 버전 개발 | 계정 정보(회원정보) | 우선순위: highest

### 요청사항
회원가입 및 회원정보 수정 시 국가를 선택할 수 있는 필드를 추가해 주세요.

### 요청한 이유
해외 사업자가 가입할 때 전화번호·사업자번호 입력 기준이 한국 형식으로 고정되어 있어 자국 정보를 입력하기 어렵습니다. 국가를 먼저 선택해야 이후 입력 항목의 기준이 맞춰집니다.

### 수정사항
- 회원가입 및 프로필 > 회원정보 수정 화면에 국가 선택(countryCode) 필드 추가
- 필수 입력, 허용 국가 리스트 내 값만 선택 가능
- 미선택 또는 허용값 외 입력 시 오류 처리
- 허용 국가 리스트업 별도 작업 필요

### 이렇게 수정한 이유
국가를 먼저 선택하면 이후 전화번호·식별번호 입력 필드가 해당 국가 기준으로 바뀐다. 이는 사용자가 "어떻게 입력해야 하나"를 추측하는 인지 부담을 없애고, 입력 전에 기대 형식을 예측할 수 있게 해준다.

## CMS-26-004 | 회원정보-전화번호 입력 유연화
> 글로벌 버전 개발 | 계정 정보(회원정보) | 우선순위: high

### 요청사항
전화번호를 국가별 형식에 맞게 자유롭게 입력할 수 있도록 해주세요.

### 요청한 이유
현재 전화번호 입력이 한국 번호 형식(010-xxxx-xxxx)에 고정되어 있어 해외 담당자나 광고주가 자국 번호를 입력할 수 없습니다.

### 수정사항
- countryCode 선행 입력 후 해당 국가 기준으로 전화번호 유효성 검증 적용
- 국가별 검증 정책을 별도 정책 문서로 관리
- 형식 오류 시 안내 메시지 표시
- 저장 표준(E.164 등) 정책 추가 논의 필요 (TBD)

### 이렇게 수정한 이유
고정된 형식 마스크(예: 010-xxxx-xxxx)가 있으면 해외 번호를 입력하는 사용자는 입력 자체가 막히는 경험을 한다. 자국 번호를 자연스럽게 입력할 수 있게 해야 "이 서비스가 나를 위한 것"이라고 느낄 수 있다.

## CMS-26-005 | 회원정보-사업자/식별번호 구조 개편
> 글로벌 버전 개발 | 계정 정보(회원정보) | 우선순위: highest

### 요청사항
사업자번호 또는 식별번호 입력을 3-2-5 고정 형식이 아닌 자유 입력으로 변경해 주세요.

### 요청한 이유
해외 사업자번호·식별번호는 한국의 3-2-5 형식과 달라 현재 구조로는 입력 자체가 불가능합니다. 글로벌 가입자가 자국 식별번호를 막힘 없이 입력할 수 있어야 합니다.

### 수정사항
- 미디어사(corpNum), 광고회사(adCompanyCorpNum) 입력을 3-2-5 형식에서 단일 자유 입력 필드로 전환 (필수 진행)
- 기존 데이터 마이그레이션은 권장 사항(우선순위 Medium)
- 입력값 인증 정책은 추후 논의 필요 (TBD)

### 이렇게 수정한 이유
3-2-5 고정 형식은 한국 사용자에게는 익숙하지만 해외 사용자에게는 완전히 낯선 제약이다. 자유 입력 필드로 전환하면 입력 방법을 알아내야 하는 부담이 사라지고 누구든 자신의 번호를 막힘 없이 입력할 수 있다.

## CMS-26-006 | 회원정보-레거시 데이터 마이그레이션
> 글로벌 버전 개발 | 계정 정보(회원정보) | 우선순위: medium

### 요청사항
기존 회원의 전화번호·사업자번호 데이터를 새로운 입력 구조에 맞게 변환해 주세요.

### 요청한 이유
입력 방식이 바뀌면 기존에 저장된 데이터가 새 구조와 맞지 않아 기존 회원 정보가 깨지거나 오류가 생길 수 있습니다. 기존 회원들이 별도 조치 없이도 정상적으로 서비스를 이용할 수 있어야 합니다.

### 수정사항
- 기존 3-2-5 형식 사업자번호를 단일 필드 형식으로 변환
- 기존 전화번호 데이터를 확정된 표준(E.164 등)에 맞게 정리
- 마이그레이션 스크립트 작성 및 실행

### 이렇게 수정한 이유
기존 사용자가 갑자기 자신의 저장된 번호가 깨져 보이거나 재입력을 요구받으면 불신과 불편함을 느낀다. 백그라운드 마이그레이션으로 사용자가 아무것도 다시 하지 않아도 되게 함으로써 전환 경험을 투명하게 만든다.

## CMS-26-007 | 미디어그룹 운영시간 타임존 반영
> 글로벌 버전 개발 | 미디어그룹 | 우선순위: highest

### 요청사항
미디어그룹 운영시간을 국가별 타임존 기준으로 설정하고 표시할 수 있게 해주세요. DST(일광절약시간제)도 반영되어야 합니다.

### 요청한 이유
해외 거점 미디어그룹의 운영시간이 서버(한국) 시간 기준으로 처리되어 현지 실제 운영시간과 맞지 않는 문제가 생깁니다. 현지 시간 기준으로 운영시간을 정확히 관리해야 합니다.

### 수정사항
- 미디어그룹 생성/수정 화면에 타임존(또는 countryCode) 선택 필드 추가
- operateFromTime/operateToTime, operateDay를 지정 타임존 기준으로 저장 및 표시
- DST 구간 시간 중복/누락 처리 정책 수립 (TBD)
- 운영시간 적용 방식 확인 필요: 서버에서 타임존 계산 후 전송하는 방식인지, 안드로이드 셋탑이 현지 시간 기준으로 자체 적용하는 방식인지 확인 후 구현

### 이렇게 수정한 이유
운영자가 "오전 9시~오후 6시 운영"이라고 설정했는데 실제 현지에서 다른 시간에 켜지고 꺼진다면 설정과 실제의 불일치로 큰 혼란이 생긴다. 타임존 기반 설정은 "내가 입력한 대로 동작한다"는 예측 가능성을 보장한다.

## CMS-26-008 | IR 센서 데이터 수집 구조/API
> 글로벌 버전 개발 | 데이터 수집/분석 | 우선순위: highest

### 요청사항
IR 센서에서 발생하는 시청자 감지 데이터를 수집하고 저장할 수 있는 구조와 API를 만들어 주세요.

### 요청한 이유
광고 효과를 정량적으로 분석하기 위해 IR 센서 데이터를 활용하고 싶은데, 현재 수집 구조와 API가 없어 센서 데이터를 전혀 활용할 수 없습니다.

### 수정사항
- IR 센서 데이터 수집 API 구성 (deviceId, sensorId, eventTime, value/count, meta 필수)
- 필수값 누락 금지, 포맷 고정(정책 수립 필요)
- 중복 적재, 비정상값, 유실 재전송 처리 정책 수립
- 운영 수집 현황/로그 화면 기획 필요 (TBD)
- 데이터 표준화 정책 및 저장/처리 용량 확보 필요

### 이렇게 수정한 이유
데이터가 수집되지 않으면 운영자가 효과 분석 화면에서 빈 화면이나 0값만 보게 된다. 수집 인프라 구축은 운영자가 의미 있는 데이터를 기반으로 결정을 내릴 수 있게 하는 UX의 전제 조건이다.

## CMS-26-009 | ColorLight LED 셋탑 전용 앱 기본 골격
> 서비스 시장 확장 | App | 우선순위: highest

### 요청사항
ColorLight LED 셋탑에서 설치·실행되는 전용 앱(권한·네트워크·저장소 포함)을 만들어 주세요.

### 요청한 이유
새로운 시장 진출을 위해 ColorLight LED 셋탑을 활용해야 하는데, 기존 앱이 해당 셋탑을 지원하지 않아 서비스 자체가 불가능합니다.

### 수정사항
- ColorLight LED 셋탑 지원 OS/스펙 확보
- 권한, 네트워크, 저장소 구조를 포함한 기본 앱 골격 구축
- 설치/실행 실패 시 사용자 안내 처리
- 배포 방식(OTA 포함) 추후 확정 (TBD)

### 이렇게 수정한 이유
앱이 설치되지 않거나 실행되지 않으면 운영자는 어디서 무엇이 잘못됐는지 알 수 없다. 기본 골격 단계에서 명확한 실패 안내를 포함해야 사용자가 문제 상황에서 다음 행동을 결정할 수 있다.

## CMS-26-010 | ColorLight LED 셋탑-의존 기능 목록화
> 서비스 시장 확장 | App | 우선순위: highest

### 요청사항
기존 앱의 어떤 기능이 ColorLight 셋탑에서 동작하고, 어떤 기능이 대체가 필요하거나 지원 불가인지 목록으로 정리해 주세요.

### 요청한 이유
어떤 기능이 그대로 사용 가능하고 어떤 기능을 새로 개발해야 하는지 파악이 안 되면 일정과 개발 범위를 예측할 수 없어 사업 계획을 세우기 어렵습니다.

### 수정사항
- 기존 Quber 앱 전체 기능 목록 작성
- 각 기능에 대해 ColorLight 동등 지원 / 대체 구현 필요 / 미지원 분류
- 필수/선택 기능 구분하여 개발 우선순위 확정
- 산출물(목록 문서) 필수 제출

### 이렇게 수정한 이유
지원하지 않는 기능을 사용자가 시도했을 때 아무런 안내 없이 동작하지 않으면 "고장난 것인지 지원 안 하는 것인지"를 알 수 없다. 미지원 여부를 명확히 분류하고 UI에서 적절히 안내해야 혼란을 방지할 수 있다.

## CMS-26-011 | ColorLight LED 셋탑-콘텐츠+스케줄 재생 호환
> 서비스 시장 확장 | App | 우선순위: highest

### 요청사항
ColorLight 셋탑에서 콘텐츠가 정상 재생되고, 스케줄에 따라 순서와 시간에 맞게 송출되어야 합니다. 즉시반영도 지원해 주세요.

### 요청한 이유
ColorLight 셋탑은 기존 Quber 셋탑과 하드웨어 구조가 달라 콘텐츠가 제대로 재생되지 않습니다. 셋탑 핵심 기능인 재생과 스케줄 적용이 동작해야 실제 서비스가 가능합니다.

### 수정사항
- ColorLight 하드웨어에 맞는 플레이어/렌더링 구현
- 지원 콘텐츠 포맷 확정 (TBD) 및 유효성 검증 적용
- 스케줄 수신 → 파싱 → 순서/시간에 따라 재생하는 전체 플로우 구현
- 즉시반영 명령 수신 시 신규 스케줄로 전환
- 재생 실패 시 로그 기록 및 재시도 정책 수립 (TBD)

### 이렇게 수정한 이유
스케줄을 설정했는데 재생이 되지 않으면 운영자는 "스케줄이 잘못된 건지, 셋탑이 고장인지, 콘텐츠 문제인지" 원인을 파악하기 어렵다. 재생 실패 시 명확한 로그와 상태 표시로 원인 파악 동선을 단축시켜야 한다.

## CMS-26-012 | ColorLight LED 셋탑-제어 명령 처리

> 서비스 고도화 | 데이터 수집/분석 | 우선순위: highest

### 요청사항
같은 물리적 위치에 복수의 미디어그룹이 있을 때, 하나의 대표 그룹으로 묶어 효과 데이터를 1건으로만 집계할 수 있게 해주세요.

### 요청한 이유
같은 장소에 여러 미디어그룹이 등록되면 동일 시청자 데이터가 중복으로 집계되어 효과 수치가 실제보다 과장됩니다. 광고주에게 정확한 수치를 제공해야 신뢰를 유지할 수 있습니다.

### 수정사항
- mediaGroupId와 mappingGroupId를 연결하는 수동 매핑 기능 구현
- 1개 mediaGroupId는 1개 mappingGroupId에만 소속 가능
- 중복 소속/매핑 누락 처리 정책 수립
- 리포트에서 mappingGroupId 단위로 1건(대표값)으로 집계하여 표시
- 대표값 선택 기준 추후 논의 (TBD)

### 이렇게 수정한 이유
같은 지점에서 시청자 수가 2배로 집계된 리포트를 보면 운영자는 수치가 이상하다는 걸 직감하지만 원인을 찾기 어렵다. 수동 매핑으로 "1개 지점 = 1건 집계"가 되어야 운영자가 리포트 수치를 있는 그대로 신뢰할 수 있다.

## CMS-26-025 | 효과 분석-중복 집계 방지(지표 계산 규칙)

성별·연령 등 지표가 동일 지점에서 중복 집계되지 않도록 지표별 계산 규칙을 적용해 주세요.

### 요청한 이유

### 수정사항
- 지표 유형별 집계 방식 정의 (단순합산/대표값/가중평균 등)

- 기준 미정 지표는 집계불가/대표값 정책 적용
- 지표별 규칙 및 대표값 기준 추후 논의 (TBD)

### 이렇게 수정한 이유
부풀려진 수치를 보고 광고주에게 잘못된 효과를 보고하면 사용자와 광고주 모두의 신뢰가 한 번에 무너진다. 정확한 집계 규칙은 리포트가 "실제 현실을 반영하는 도구"로서의 가치를 유지하는 근거가 된다.

- 상세 탭: 개별 재생 이벤트 단위 로그 제공 (CMS-26-046 연계)
- 두 탭에서 동일한 dateRange 필터 공유

### 이렇게 수정한 이유
집계 수치와 이벤트 로그가 한 화면에 섞여 있으면 필요한 정보를 찾는 데 시간이 걸리고 화면이 복잡해 보인다. 요약/상세 탭 분리는 "빠른 확인"과 "깊은 분석"이라는 서로 다른 사용자 목적을 각각 최적화된 화면으로 지원한다.

## CMS-26-046 | 재생로그-세부 정보 제공(이벤트 단위)
> 서비스 고도화 | 모니터링 | 우선순위: medium

### 요청사항
선택 기간 동안의 개별 재생 이벤트를 건별로 조회하고 다운로드할 수 있게 해주세요.

### 요청한 이유
광고 송출 검증이나 분쟁 처리 시 특정 콘텐츠가 언제 재생됐는지 이벤트 단위로 확인해야 하는데, 현재는 집계 수치만 제공되어 증빙 자료로 활용하기 어렵습니다.

### 수정사항
- 재생로그(상세) 탭에서 dateRange, mediaId/deviceId, contentId 기반 이벤트 목록 무한 스크롤 조회
- 각 이벤트에 콘텐츠 식별 정보 + 송출 시각 필수 포함
- 최대 조회 기간 제한 정책 수립
- 대용량 조회 시 로딩/부분 로딩 처리
- 데이터 없음/조회 실패 상태 처리
- 다운로드 기능 제공

### 이렇게 수정한 이유
"이 콘텐츠가 오전 10시 27분에 실제로 나갔는가"를 확인해야 하는데 집계 수치만 있다면 운영자는 근거를 제시할 수 없어 분쟁 상황에서 무력해진다. 이벤트 단위 로그는 운영자가 언제든 구체적인 근거를 화면에서 꺼낼 수 있는 신뢰의 도구가 된다.

## CMS-26-048 | 다중 선택 UX 제공
> 서비스 고도화 | 공통 리스트 | 우선순위: medium

### 요청사항
리스트 화면에서 여러 항목을 한 번에 선택할 수 있는 체크박스 UI를 제공해 주세요.

### 요청한 이유
항목을 하나씩 선택해서 처리하면 시간이 너무 걸립니다. 특히 대량 작업 시 여러 개를 한꺼번에 선택할 수 있어야 효율적입니다.

### 수정사항
- 리스트 화면에 체크박스 기반 다중 선택 UI 추가
- selectedIds 1개 이상 선택 가능
- 선택 0개 상태에서 액션 실행 제한
- 조건 미충족 대상(예: 운영중 스케줄) 선택 불가 처리
- 기본 동작(전체선택/필터 변경 시 선택 유지) 정책 확정 필요

항목 100개를 하나씩 클릭해서 삭제해야 한다면 반복 조작 피로가 쌓이고 실수로 잘못된 항목을 클릭할 수 있다. 다중 선택은 반복 조작을 한 번의 선택으로 압축하여 작업 효율을 높이고 실수 공간을 줄인다.

## CMS-26-049 | 일괄 삭제/복제 액션 제공
> 서비스 고도화 | 공통 리스트 | 우선순위: medium

### 요청사항
여러 항목을 선택하여 한 번에 삭제하거나 복제할 수 있는 일괄 처리 기능을 제공해 주세요.

### 요청한 이유
유사한 광고 설정을 반복적으로 만들거나 불필요한 항목을 대량으로 정리해야 할 때 하나씩 처리해야 해서 매우 비효율적입니다.

### 수정사항
- selectedIds, action(delete/copy) 기반 일괄 처리
- 선택 항목 1개 이상 조건 검증
- 삭제·복제 조건(운영중 등) 검증 후 처리 차단/안내
- 부분 실패 시 성공/실패 목록 구분 안내

## CMS-26-050 | 대시보드 그래프 인터랙션 개선
> 서비스 고도화 | 대시보드 | 우선순위: low

### 요청사항
대시보드 그래프에서 마우스오버 시 수치 툴팁이 표시되고, 항목 클릭 시 상세 데이터로 이동할 수 있게 해주세요.

### 요청한 이유
현재 그래프가 정적으로만 표시되어 특정 날짜나 항목의 상세 수치를 확인하기 위해 별도 화면으로 이동해야 합니다. 그래프에서 바로 궁금한 정보를 확인하고 싶습니다.

### 수정사항
- 그래프 마우스오버 시 툴팁으로 상세 수치 표시

- 드릴다운 또는 필터 연동으로 관련 상세 화면으로 이동 가능

## CMS-26-051 | 플로팅 버튼 제공 로직 개선
> 서비스 고도화 | 공통 | 우선순위: low

### 요청사항
플로팅 버튼이 관련 화면에서만 일관되게 노출되도록 노출 조건과 동작을 정리해 주세요. 중복 노출과 오작동이 없어야 합니다.

### 요청한 이유
현재 플로팅 버튼이 화면과 무관하게 나타나거나 중복으로 표시되는 경우가 있어 혼란스럽고 의도치 않은 클릭이 발생할 수 있습니다.

### 수정사항
- 페이지/권한/스크롤/상태 기반 노출 조건 정의
- 노출 조건 및 버튼 액션 정의 완료 후 구현
- 중복 노출 방지 로직 추가
- 대시보드/공통 영역 전반에 적용

### 이렇게 수정한 이유
플로팅 버튼이 의도치 않은 화면에서 보이거나 중복으로 나타나면 "이 버튼을 눌러야 하나"라는 혼란과 잘못된 클릭 위험이 생긴다. 일관된 노출 조건은 사용자가 "이 버튼이 보이면 지금 사용할 수 있다"는 신뢰를 형성하게 하여 화면과 사용자 간의 예측 가능한 관계를 만든다.
